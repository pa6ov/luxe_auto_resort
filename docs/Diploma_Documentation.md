# Дипломен проект: Luxe Auto Resort

## Уеб приложение за наемане на автомобили

---

## 1. Увод

### 1.1. Цел и задача

Настоящият дипломен проект има за цел разработването на цялостно уеб приложение за наемане на автомобили, наречено "Luxe Auto Resort". Приложението предоставя платформа, чрез която клиентите могат да разглеждат наличните автомобили, да правят резервации и да управляват своите наеми. Администраторите на системата имат възможност да управляват автомобилите, шаблоните за наеми, заявките на клиентите и да следят статистики за бизнеса.

Проектът е разработен като модерно, отзивчиво (responsive) уеб приложение, което работи на различни устройства - от персонални компютри до мобилни телефони. Използваните технологии включват HTML, CSS и JavaScript за клиентската част, Node.js и Express за сървърната част, както и MySQL за управление на данните.

### 1.2. Актуалност и предназначение

Съвременният живот изисква гъвкавост и удобство във всеки аспект от ежедневието, включително и в наемането на превозни средства. Традиционните методи за резервация на автомобили, които изискват физическо посещение на място или телефонни обаждания, вече не отговарят на очакванията на модерния потребител. Дигитализацията на този процес не само улеснява клиентите, но и оптимизира работата на компанията, намалявайки административните разходи и грешките, свързани с човешкия фактор.

Уеб приложението "Luxe Auto Resort" е предназначено да задоволи тези нужди, като предоставя интуитивен интерфейс за търсене и резервация на автомобили по всяко време и от всяко място с интернет връзка. Системата е проектирана да обслужва както крайни клиенти, така и администратори, осигурявайки различни нива на достъп и функционалност според ролята на потребителя.

### 1.3. Предимства на автоматизацията

Автоматизацията на процеса по наемане на автомобили носи множество предимства:

- **24/7 достъпност**: Клиентите могат да правят резервации по всяко време, без да чакат работното време на компанията
- **Бързина и ефективност**: Процесът на резервация отнема минути, вместо часове
- **Намаляване на грешките**: Автоматизираните изчисления на цени и отстъпки елиминират човешките грешки
- **По-добро управление на ресурсите**: Администраторите имат ясна представа за наличността на автомобилите
- **Аналитика и отчети**: Системата генерира ценна информация за най-наеманите автомобили, предпочитанията на клиентите и приходите
- **Multi-vehicle резервации**: Възможност за наемане на няколко автомобила в една заявка

## 2. Анализ на технологиите

### 2.1. HTML (HyperText Markup Language)

HTML е основният език за създаване на уеб страници. В този проект HTML5 се изполва за структуриране на всички страници на приложението. Основните предимства на HTML включват:

- **Семантични елементи**: Елементи като `<header>`, `<nav>`, `<section>`, `<footer>` подобряват достъпността и SEO оптимизацията
- **Поддръжка на мултимедия**: Вградена поддръжка за изображения, видео и аудио
- **Формуляри**: Мощни възможности за събиране на потребителски данни
- **Адаптивен дизайн**: HTML5 е в основата на responsive уеб дизайна

### 2.2. CSS (Cascading Style Sheets)

CSS е езикът за стилизиране на уеб страници. В проекта се използва CSS3 с множество модерни техники:

- **CSS Variables**: Позволяват лесно управление на цветовата палитра и повтарящи се стойности
- **Flexbox и Grid**: Модерни техники за layout, които заменят табличния дизайн
- **Media Queries**: За постигане на responsive дизайн на различни устройства
- **Animations и Transitions**: Плавни визуални ефекти за по-добро потребителско изживяване

**Цветова схема:**
```css
:root {
  --bg: #171614;        /* Тъмен фон */
  --accent: #4B88A2;    /* Акцентен син */
  --card: #ECE5F0;      /* Светъл фон за карти */
  --cta: #E98A15;       /* Оранжев за CTA бутони */
}
```

### 2.3. JavaScript

JavaScript е програмният език, който прави уеб страниците интерактивни. Използва се ванилен JavaScript (без рамки) поради следните предимства:

- **Лесна поддръжка**: Няма нужда от допълнителни библиотеки и зависимости
- **Бързо зареждане**: По-малка големина на файловете в сравнение с рамките
- **Универсална съвместимост**: Работи във всички модерни браузъри
- **Пълнота на контрола**: Пълен контрол върху поведението на страницата

### 2.4. Node.js

Node.js е среда за изпълнение на JavaScript от страна на сървъра. Избрана е поради:

- **Език Единство**: Използва се един и същ език (JavaScript) за клиент и сървър
- **Асинхронна архитектура**: Идеална за I/O операции като заявки към база данни
- **Богата екосистема**: NPM (Node Package Manager) предоставя хиляди модули
- **Бързина**: V8 двигателят на Google осигурява висока производителност

### 2.5. Express.js

Express.js е минималистична уеб рамка за Node.js, която опростява разработката на сървърни приложения:

- **Маршрутизация**: Лесно дефиниране на API endpoints
- **Middleware**: Модулна архитектура за обработка на заявки
- **Шаблони**: Поддръжка на различни шаблонни езици
- **Статични файлове**: Вградена поддръжка за статични ресурси

### 2.6. MySQL

MySQL е релационна система за управление на бази данни. Изборът ѝ е продиктуван от:

- **Надеждност**: Доказана стабилност в продължение на години
- **SQL стандарт**: Използва стандартния SQL език за заявки
- **ACID съответствие**: Гарантира целостта на данните
- **Производителност**: Оптимизирана за големи обеми от данни
- **Широка поддръжка**: Добра документация и общност

### 2.7. Сравнителен анализ

| Технология | Предимства | Недостатъци | Избор за проект |
|------------|-----------|-------------|-----------------|
| **Frontend рамки (React, Vue)** | Богата функционалност, компонентен модел | По-висока сложност, по-бавно зареждане | ❌ |
| **Vanilla JS** | Бързо, лесно, пълен контрол | Повече код за сложни функционалности | ✅ |
| **PHP** | Широко разпространен, добра документация | По-ниска производителност | ❌ |
| **Python/Django** | Бърза разработка, вграден ORM | По-тежък, по-висок footprint | ❌ |
| **SQL vs NoSQL** | SQL предлага по-добра структура и връзки | NoSQL по-гъвкав за неструктурирани данни | MySQL ✅ |

## 3. Анализ на нуждите

### 3.1. Идентифицирани потребители

Системата обслужва два основни типа потребители:

**Клиенти:**
- Търсят и разглеждат налични автомобили
- Филтрират по различни критерии (цена, тип, марка)
- Създават заявки за наем
- Преглеждат своите заявки и техния статус
- Оставят коментари и отзиви
- Могат да избират няколко автомобила в една заявка

**Администратори:**
- Управляват автомобилите (CRUD операции)
- Управляват шаблоните за наеми
- Преглеждат и одобряват/отхвърлят заявки
- Модерират коментарите
- Преглеждат контактни съобщения
- Следят статистики и отчети

### 3.2. Функционални изисквания

**За всички посетители:**
- Преглед на каталог с автомобили
- Търсене и филтриране на автомобили
- Преглед на детайли за автомобил
- Преглед на шаблони/пакети
- Четене на одобрени коментари
- Изпращане на контактно съобщение

**За регистрирани клиенти:**
- Всички функции на посетител
- Регистрация и вход в системата
- Създаване на заявки за наем
- Multi-select на автомобили
- Избор на шаблон или свободен избор
- Преглед на личните заявки
- Отмяна на чакащи заявки
- Преглед на разходите
- Оставяне на коментари

**За администратори:**
- Всички функции на клиентите
- CRUD за автомобили
- CRUD за шаблони
- Преглед на всички заявки
- Промяна на статус на заявки (pending → approved/rejected → completed)
- Модерация на коментари (pending → approved/rejected)
- Преглед на контактни съобщения
- Dashboard със статистики (приходи, топ автомобили, брой клиенти)

### 3.3. Нефункционални изисквания

**Сигурност:**
- Паролите се съхраняват като хеш (bcrypt с 10+ rounds)
- JWT базирана автентикация с 24-часова валидност
- Middleware за защита на админски маршрути
- Валидация на входни данни на ниво сървър
- SQL injection защита чрез параметризирани заявки
- CORS конфигурация за контрол на достъпа

**Производителност:**
- Оптимизирани SQL заявки с индекси
- Connection pooling за базата данни
- Асинхронна обработка на заявки
- Ефективна обработка на грешки без изтичане на информация

**Достъпност:**
- Responsive дизайн за всички устройства
- Semantic HTML за screen readers
- Добър контраст на цветовете
- Интуитивна навигация

### 3.4. Ограничения

- Приложението работи локално (localhost) или в частна мрежа
- Базата данни изисква MySQL сървър
- Няма интеграция с платежни системи
- Няма email известия (контактните съобщения се записват само в DB)
- Няма SMS известия
- Няма интеграция с външни календари

#### 4.2.2. Описание на таблиците

**users (Потребители)**
- Съхранява информация за всички потребители на системата
- Полета: id, email (unique), password (bcrypt hash), first_name, last_name, phone, role (admin/client)
- Индекси: idx_email, idx_role

**cars (Автомобили)**
- Съхранява информация за всички автомобили, предлагани за наем
- Полета: id, brand, model, year, color, license_plate (unique), price_per_day, type, seats, transmission, fuel_type, mileage, image_url, description, available
- Индекси: idx_brand, idx_model, idx_price, idx_available, idx_type

**templates (Шаблони)**
- Съхранява пакети/шаблони за наем с продължителност и отстъпки
- Полета: id, name, description, duration_days, discount_percent, is_active
- Индекс: idx_active

**template_options (Опции)**
- Съхранява допълнителни опции и екстри за всеки шаблон
- Полета: id, template_id (FK), name, price, is_included

**rental_requests (Заявки)**
- Съхранява всички заявки за наем от клиенти
- Полета: id, user_id (FK), template_id (FK), start_date, end_date, total_price, status, notes
- Статуси: pending, approved, rejected, completed, cancelled
- Индекси: idx_user, idx_status, idx_dates, idx_created

**request_cars (Много към много)**
- Връзка между заявки и автомобили (multi-select)
- Полета: id, request_id (FK), car_id (FK)
- Unique constraint: (request_id, car_id)

**contact_messages (Съобщения)**
- Съхранява контактни съобщения от посетители
- Полета: id, name, email, subject, message, is_read, created_at

**platform_comments (Коментари за платформата)**
- Съхранява коментари за платформата
- Полета: id, user_id (FK, nullable), guest_name, content, rating (1-5), status, created_at
- Статуси: pending, approved, rejected

**template_comments (Коментари за шаблони)**
- Съхранява коментари за конкретни шаблони
- Полета: id, user_id (FK), template_id (FK), content, rating (1-5), status, created_at

#### 4.2.3. Индекси и оптимизация

За оптимизиране на производителността са създадени следните индекси:
- `idx_email` в таблица users - за бърз вход
- `idx_role` в таблица users - за филтриране по роля
- `idx_brand`, `idx_price`, `idx_available`, `idx_type` в таблица cars - за филтриране и сортиране
- `idx_status`, `idx_user`, `idx_dates` в таблица rental_requests - за dashboard и потребителски заявки
- Foreign key индекси за всички релации

#### 5.2.2. Автентикация

Използва се JWT (JSON Web Token) за сигурна автентикация:

```javascript
// Генериране на токен при вход
const token = jwt.sign(
  { id: user.id, email: user.email, role: user.role },
  JWT_SECRET,
  { expiresIn: '24h' }
);
```

Middleware за защита на маршрути:
- `requireAuth` - проверява дали потребителят е влязъл, валидира JWT токена
- `requireAdmin` - проверява дали потребителят има роля 'admin'

**Сигурност:**
- Паролите се хешират с bcrypt (10 salt rounds)
- JWT токените изтичат след 24 часа
- Секретният ключ може да се конфигурира чрез environment variable

#### 5.2.4. Обработка на грешки и валидация

За да се осигури стабилност и предвидимост, е изграден централизиран механизъм за обработка на грешки и валидация в `backend/utils/errors.js`.

**Custom Error Classes:**
Създадени са персонализирани класове за грешки:
- `AppError` - Базов клас за оперативни грешки
- `ValidationError` (400) - Невалидни входни данни
- `AuthError` (401) - Проблеми с автентикацията
- `ForbiddenError` (403) - Недостатъчни права
- `NotFoundError` (404) - Ресурсът не е намерен
- `ConflictError` (409) - Конфликт (напр. дублиран email)
- `DatabaseError` (500) - Проблеми с базата данни

**Error Codes:**
Дефиниран е обект `ErrorCodes` с константни стойности:
- Auth: `INVALID_CREDENTIALS`, `EMAIL_ALREADY_EXISTS`, `TOKEN_EXPIRED`, `UNAUTHORIZED`, `FORBIDDEN`
- Validation: `VALIDATION_ERROR`, `REQUIRED_FIELD`, `INVALID_DATE`, `DATE_IN_PAST`
- Resource: `NOT_FOUND`, `ALREADY_EXISTS`
- Server: `DATABASE_ERROR`, `INTERNAL_ERROR`

**Async Handler:**
```javascript
const asyncHandler = (fn) => (req, res, next) => {
  Promise.resolve(fn(req, res, next)).catch(next);
};
```
Този wrapper елиминира нуждата от `try...catch` във всеки route handler.

**Validation Helpers:**
```javascript
validate.email(email);           // Валидация на email формат
validate.password(password);     // Мин. 6 символа, буква + цифра
validate.dateNotPast(date);      // Дата не може да е в миналото
validate.minLength(value, 2, 'Име');  // Минимална дължина
```

**Centralized Error Handler:**
Обработва различни типове грешки:
- Оперативни грешки (AppError) - връща се съответния HTTP статус
- JWT грешки (JsonWebTokenError, TokenExpiredError) - 401
- MySQL грешки (ER_DUP_ENTRY, ER_NO_REFERENCED_ROW_2) - 409/400
- Неочаквани грешки - 500 без изтичане на детайли

**Формат на отговор при грешка:**
```json
{
  "success": false,
  "error": {
    "message": "Моля, поправете грешките във формата",
    "code": "VALIDATION_ERROR",
    "details": [
      { "field": "email", "message": "Имейлът е задължителен" },
      { "field": "password", "message": "Паролата трябва да е поне 6 символа" }
    ]
  }
}
```

**1. Конфигурация на средата:**
- **Променливи на средата (.env)**: Всички чувствителни данни като пароли за базата данни, `JWT_SECRET` и други конфигурационни параметри трябва да бъдат изнесени от кода и управлявани чрез `.env` файл. Това позволява лесна конфигурация за различни среди (development, staging, production) и предпазва от случайно публикуване на секретни данни в git хранилище.
- **Режим на Node.js**: Приложението трябва да се стартира в продукционен режим чрез `NODE_ENV=production`. Това активира оптимизации в Express, които подобряват производителността и сигурността.

**2. Управление на процеса:**
- **Process Manager (PM2)**: В продукционна среда Node.js сървърът трябва да се управлява от process manager като PM2. PM2 осигурява автоматично рестартиране на приложението при срив, клъстеризация за използване на всички CPU ядра (load balancing) и лесен мониторинг и логване.
  - Примерна команда за стартиране: `pm2 start backend/server.js --name luxe-auto-resort`
  - Запазване на конфигурация: `pm2 save`
  - Автоматично стартиране: `pm2 startup`

**3. Уеб сървър и Reverse Proxy:**
- **Nginx**: Препоръчително е Node.js приложението да не бъде директно изложено към интернет. Вместо това, пред него трябва да се постави reverse proxy като Nginx. Това носи следните ползи:
  - **SSL/TLS Termination**: Nginx може да управлява HTTPS криптирането чрез Let's Encrypt или друг сертификат.
  - **Кеширане на статични ресурси**: Nginx може ефективно да кешира и сервира статичните файлове (`/frontend`), намалявайки натоварването на Node.js сървъра.
  - **Rate Limiting**: Защита от brute force атаки и DDoS.
  - **Compression**: Gzip компресия на отговорите.

**Примерна Nginx конфигурация:**
```nginx
server {
    listen 80;
    server_name luxeautoresort.com;

    location / {
        proxy_pass http://localhost:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
    }
}
```

- **CDN**: Използване на Content Delivery Network за статични ресурси (Cloudflare, AWS CloudFront).

**6. Мониторинг и логване:**
